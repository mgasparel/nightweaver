# Beads-native Agent handoff and thin Orchestrator

Instead of sandboxed JSON workers, local state file persistence, or `bd formula` sub-bead molecules, Nightweaver keeps workflow state on the **Product Bead** and **Plan Bead** in `bd` labels and comments. **Agents** (`Planner`, `Plan Challenger`, `Implementer`, `Reviewer`, `QA`, `Merger`) execute `bd`, `git`, and `gh` operations within their role boundaries and supply findings for Orchestrator verification.

Before live startup recovery or dispatch writes, the **Orchestrator** validates the Target Repository read-only and acquires an OS-managed process-lifetime mutex keyed to the physical Git common directory. The mutex applies across Project names and Nightweaver host roots, stays outside the Target Repository, and releases when its owning process exits or dies; recovery uses no lease database, heartbeat, PID file, or proof-of-death service. Under exclusion, startup releases only claims still `in_progress` and assigned exactly to the current Project's recovery actor, using status and assignee guards and fresh reads around uncertain writes. It preserves stage, pause labels, repair counts, and all other Bead fields, then reads actual current inventory and native readiness before admission. Foreign and other-Project claims remain untouched. Required tracker failures and unusable shared runtime roots stop startup. `--dry-run` inspects the same proposed recovery without acquiring recovery authority. Startup recovery decisions do not authorize Agents to adopt or release claims, and comments alone never resume a Bead.

Human pause is an environment-retention boundary: keep the local worktree, current branch and `HEAD`, all tracked and untracked files, ignored caches, logs, and Bead temporary files so a person can inspect or resume the work; release only the claim still owned by Nightweaver. A validated resume reuses the retained checkout without an implicit fetch or reset. This clarifies environment disposition and does not change transition authority: the `ns-jbp` and `ns-yrh.8` decisions supersede earlier guidance that allowed Agents to write lifecycle transitions.
