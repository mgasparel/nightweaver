# Beads-native Agent handoff and thin Orchestrator

Instead of sandboxed JSON workers, local state file persistence, or `bd formula` sub-bead molecules, Nightweaver keeps workflow state on the **Product Bead** and **Plan Bead** in `bd` labels and comments. **Agents** (`Planner`, `Plan Challenger`, `Implementer`, `Reviewer`, `QA`, `Merger`) execute `bd`, `git`, and `gh` operations within their role boundaries and supply findings for Orchestrator verification.

Before live startup recovery or dispatch writes, the **Orchestrator** validates the Target Repository read-only and acquires an OS-managed process-lifetime mutex keyed to the physical Git common directory. The mutex applies across Project names and Nightweaver host roots, stays outside the Target Repository, and releases when its owning process exits or dies; recovery uses no lease database, heartbeat, PID file, or proof-of-death service. Under exclusion, startup releases only claims still `in_progress` and assigned exactly to the current Project's recovery actor, using status and assignee guards and fresh reads around uncertain writes. It preserves stage, pause labels, repair counts, and all other Bead fields, then reads actual current inventory and native readiness before admission. Foreign and other-Project claims remain untouched. Required tracker failures and unusable shared runtime roots stop startup. `--dry-run` inspects the same proposed recovery without acquiring recovery authority. Startup recovery decisions do not authorize Agents to adopt or release claims. Comments, notes, description edits, and audit history supply context only; they never authorize execution.

The current selector-only CLI connects that recovered state to a continuous Delivery runtime. Startup, best-effort journal event hints from the configured Target Repository, an always-on 30-second timer, and Delivery completions after local capacity release share one coalesced, serialized discovery path. Each pass reads fresh eligibility, reserves bounded local capacity, and queues preparation without waiting for an Agent attempt. Failed tracker reads admit no stale work and wait for a later trigger. Journal setup and attachment do not gate startup or require historical replay. Tail termination or truncation requests discovery and reconnects with capped exponential backoff while timer and completion triggers remain active. Planning and Merger runtime integration remain later work.

The first `Ctrl+C` closes new reservations and native Agent-launch boundaries before stopping discovery. Preparation already in flight settles without launching; an already launched turn can complete verification, bounded outcome classification including its permitted fallback, and guarded result recording under its ordinary timeout. Shutdown starts no next role, operational retry, duplicate-failure classifier, or retry-only reset. It rereads ownership before guarded claim finalization, retains unfinished and paused work, and drains every slot without a fixed two-minute cutoff. A failed turn or required finalization/read failure makes shutdown unsuccessful after the other slots drain. A second signal atomically closes all active Agent Job Objects and exits unsuccessfully without awaiting executor cleanup, classification, Git/Beads operations, verification, resets, environment cleanup, or claim release. It starts no fallback or compensating writes, later signals do not extend shutdown, and the repository mutex remains held through process exit. Restart rereads actual tracker/filesystem state and performs ordinary guarded recovery while retaining unfinished and paused work.

Live startup performs completed-environment cleanup after exact-claim recovery and before fresh admission reads. The **Orchestrator** removes only a `planned` Product Bead's detached Planning worktree or a closed Plan Bead's exact Delivery branch checkout after fresh Bead, registration, canonical-path, ownership, lock, linkage, and path-safety checks. A new pause or changed checkout identity cancels a stale candidate. Locked, missing/prunable, unregistered, linked, deleted-Bead, and ambiguous leftovers remain and are diagnosed. Cleanup uses targeted `git worktree remove --force`; it never runs startup-wide `git worktree prune` or deletes branches by name. Tmp deletion follows observed surviving worktrees and directories and applies only to known completed Beads. Local failures record path and reason, add a human pause without reopening closed status, protect remaining resources, and allow unrelated cleanup to proceed. Failure to persist required escalation state stops startup; successful prior cleanup is not rolled back.

Human pause is an environment-retention boundary: keep the local worktree, current branch and `HEAD`, all tracked and untracked files, ignored caches, logs, and Bead temporary files so a person can inspect or resume the work; release only the claim still owned by Nightweaver. A human resumes paused work through the Attention Desk's explicit Resume or Retry action. The request carries the displayed stage, full pause-label set, and repair count; the host compares them with fresh state before writing an audit comment. One native update guarded for open status and an empty assignee removes both pause labels and unsets `repair_cycles`, preserving the current stage and unrelated fields. Abort closes without clearing pause state or repair budget. If the state update fails or its result is uncertain, current tracker reads determine the reported outcome; an audit comment is never treated as a command. Only a successful persisted Resume or Retry makes the Bead eligible for ordinary dependency, capacity, stage, and claim scheduling. The action does not directly launch an Agent, and fresh discovery after restart uses the same rules. A validated resume reuses the retained checkout without an implicit fetch or reset. Lifecycle authority belongs to the Orchestrator for every Delivery role, not only Implementer.

Implementer, Reviewer, and QA are evidence-producing workers, not workflow-state owners. Implementer may edit, commit, push, and create or update its pull request. Reviewer and QA perform their assigned review or verification work. Each records findings, checks, and any concrete product question in the existing invocation log or Bead comments. None changes status, type, stage or pause labels, assignee, or `repair_cycles`. After each process exits, the Orchestrator collects bounded evidence with source IDs, classifies it using role-specific allowed outcomes, independently checks process/worktree/Git and tracker state, and publishes the verified result under current status and assignee guards.

Delivery outcome classification uses one OpenAI Decisions choice request as primary and at most one configured standard Agent CLI classifier fallback with the same question, choices, and evidence. Implementer outcomes are `ready_for_review`, `product_decision_required`, `technical_blocker`, and `incomplete_or_unclear`; Reviewer and QA outcomes are `approved`, `changes_required`, `product_decision_required`, `technical_blocker`, and `incomplete_or_unclear`. Missing credentials or unavailable or invalid primary responses invoke the fallback; a valid unclear or non-approval answer stops immediately. Invalid or unavailable fallback, failed independent verification, or a technical blocker preserves the work and evidence, leaves the input stage and repair counter unchanged, and escalates to `needs-human` without an operational retry or another Delivery role run. A verified approval advances to the next stage; a verified repair finding returns to `stage:implement` with the shared repair count incremented in the same guarded update. A verified concrete product question publishes its pause state and releases the claim in one guarded update. QA approval publishes `stage:merge`, opens the Bead, and clears the assignee atomically. The receipt is accepted from the structured update result; if that result is ambiguous, one fresh read may confirm it. After confirmed handoff, the Delivery slot performs no more Bead or worktree operations. This outcome classifier is separate from the existing duplicate operational failure classifier. No classification queue, decision ledger, replay marker, or new workflow stage is introduced.
