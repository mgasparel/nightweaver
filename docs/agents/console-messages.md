# Console message presentation

Bead comments remain exact, immutable inputs to the console's read-only presentation projection. `CommentPresenter` supports Merger rejection, needs-human escalation (current `environment_retention` and historical `cleanup_preflight`), supplemental pause/cleanup failure, and nested Planning question v1 comments. The same projected message is rendered in Workspace history, selected Workspace pause context and Human Attention Desk.

Reported failures and host verification failures are separate events. The display never establishes a new check result, infers root cause from a scenario name, or joins events because they are close in time. Supplemental pause reports stay separately attributed; up to three are available alongside selected context, with the full history available in the Workspace. Cause, reason, findings, retention warnings and evidence references have separate labels. Nested JSON inside a findings string remains literal text.

Source selection uses the containing Bead identity and stable comment identity. The newest primary schema-like diagnostic or structured question is selected even when unsupported or malformed, so an older explanation cannot silently appear current. Ordinary notes do not replace structured pause evidence. Legacy prose questions remain supported when no structured question is available. Unsupported or mismatched records explicitly qualify uncertainty and retain the original for inspection. Chronological selection does not verify that a workflow transition succeeded.

Parsing is bounded to 256 Ki characters and 24 JSON levels. Adapters validate required fields, provided field types, allowed enums and duplicate properties, including nested data. Harmless extra fields are preserved in the original disclosure. Unsupported contracts, including classifier-only contracts, remain inspectable fallbacks.

Delivery, Merger and Planning publication comments show the host-recorded role, reported outcome, classification reason, provider and invocation references. The overloaded Merger classifier shape (`question`/`choice`) is explicitly unsupported, as are Planner/Challenger classifier contracts and role evidence documents. Host outcome comments can precede a failed state update; they never establish observed workflow success.

Human notes and Resume, Retry and Abort requests show the actor and requested action. Instructions remain primary content. These audit records describe intent even when the accompanying update failed or is uncertain. The browser uses the shared projection rather than extracting instructions from raw JSON.

The projection also carries the audit's history kind (`human-guidance` or `human-action`), preserving existing history consumers while supporting semantic display. Attention Desk classification consumes this kind directly, removing the older second guidance parser. It does not control pause selection or action eligibility.

Exact v1 merge text distinguishes agent reports from host-recorded verified merge evidence. PR, checked head, merge commit, reported check result and source comment remain available in labelled details. Unknown or malformed prefix records fall back explicitly. Finalization diagnostics retain their literal cleanup and Product-completion meaning independently of the merge report. Viewing a source's check claim does not verify it. Source references resolve to keyboard-accessible links in the current Workspace history, including collapsed older comments; unavailable references remain labelled text.

Planning candidates and reviews use the producer's camelCase evidence shape. Candidate task context, outcome, advisory approach, acceptance criteria, verification, dependencies, sourced constraints, coverage and grounding stay behind disclosures. Review assessment remains distinct from findings, questions, recommendations, tradeoffs and targeted revalidation. Host publications use snake_case approval identity and grounding, with candidate/review IDs and hashes available in details. Neither review assessment nor host-recorded approval establishes current freshness or authorizes task publication. Long summaries are excerpted with full text on demand; all exact originals remain available.

Verbose fields use bounded excerpts and keyboard disclosures; exact comments and additional technical data remain available. Disclosure identity includes the surface and source comment ID, retaining state and focus across refresh. Payload text is inserted as text, never HTML. Local paths and unsafe URLs remain literal, selectable references. Absolute HTTP(S) evidence URLs without credentials or whitespace are keyboard-accessible links that open in a separate tab only on explicit activation. Rendering, expanding and refreshing do not fetch their destinations, serve files, or invoke actions. Top-level schema claims are inspected across duplicate fields and invalid value types; nested examples in other fields cannot displace pause evidence.

Presentation state never controls workflow authority. Existing fresh status, claim, stage, full pause-label and repair-count guards continue to govern explicit human actions. Neither a displayed question nor an ordinary note authorizes Resume or Retry.

Verification is in `CommentPresentationTests`, the existing Web action/boundary suite, and the isolated `schema-messages` browser scenario documented in the QA AppHost README.
